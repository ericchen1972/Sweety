# ChatGPT 對 Sweety 的觀點首頁區塊設計

## 目標

把 `README.md` 中完整的「ChatGPT 對 Sweety 的觀點」帶到公開首頁，放在「使用說明」現有說明、強調引言與開源提示之後，以及第一張操作教學圖片之前。首頁的繁體中文、英文與日文語系都要提供對應內容。

## 呈現方式

區塊預設直接顯示標題、來源說明、核心論點與最終結論「能聊下去，什麼也不代表」。其餘完整內容放在同一區塊的原生展開控制中，讓訪客自行開啟閱讀，避免長文把七張使用教學圖片推得過遠。

視覺沿用首頁現有淡藍色、藍色左框與圓角語言，做成獨立但不搶過「使用說明」主標題的觀點卡片。長文中的強調句、兩組漏斗數據、流程示意、三點清單與 ROI 公式保留各自的語意層級。桌面與手機皆為單欄，程式碼式數據區塊可以在自身範圍捲動，但頁面不得出現水平溢位。

## 多語內容

- 繁體中文以 `README.md` 原文為唯一基準，不改寫核心意思或數據。
- 英文與日文提供忠實翻譯，保留相同段落順序、數字、公式、重點與結論。
- 三種語言都包含可見標題、來源說明、摘要、展開／收合標籤與完整長文。
- 語系切換沿用 `web/homepage.js` 現有 `data-copy` 與 `textContent` 更新機制，不新增 HTML 注入路徑。

## 結構與資料流

`web/index.html` 提供可存取的靜態英文 fallback 與觀點區塊結構。`web/homepage.js` 在既有三語 copy 物件中提供每個文字欄位及陣列，並由現有語系套用流程更新文字節點。清單與多行數據使用明確的資料掛鉤更新，避免以 `innerHTML` 載入翻譯內容。

展開控制使用原生 `<details>`／`<summary>`，即使 JavaScript 未執行仍能操作；切換語系時保留目前的展開狀態。

## 驗證

- 先在 `web/tests/homepage.test.mjs` 增加失敗測試，確認三語資料完整且結構一致。
- 驗證首頁包含正確位置、可存取的展開控制，以及所有多語掛鉤。
- 執行首頁完整測試與 `git diff --check`。
- 依既有契約更新 `homepage.css + NUL + homepage.js` 的 SHA-256 前 12 碼，並同步兩個資源 URL。
- 以桌面與手機尺寸檢查預設摘要、展開全文、文字層級及水平溢位。
